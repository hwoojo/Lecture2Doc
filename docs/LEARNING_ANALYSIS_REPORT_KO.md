# Lecture2Doc 강의 학습 분석 및 캐시 최적화 보고서

- 작성일: 2026년 11월 10일
- 작업 브랜치: `기능/강의-중요도-시간연결.time`
- 기반 브랜치: `feature/frame-speed`
- 목표: 원본 강의의 판서·음성·시간 근거를 보존하면서, 학습자가 중요한 구간을 우선 확인하도록 돕는다.

## 1. 요약

이번 작업은 두 가지 개발을 하나의 브랜치에 결합했다.

1. 기존 프레임 특징 캐시 최적화: 영상 분석 단계에서 이미 계산한 판서 특징을 페이지 정리 단계가 다시 계산하지 않고 재사용한다.
2. 신규 강의 학습 분석: 판서 OCR과 자막·Whisper 음성 전사를 연결해 페이지별 중요도와 개념별 등장 시각을 제공하고, 로컬 Qwen3-VL이 준비된 경우 강의 문맥에 맞는 핵심 개념을 최대 5개 선별한다.

따라서 새 브랜치는 캐시 최적화만 포함한 `feature/frame-speed`를 기반으로 하며, 기존 최적화를 제거하거나 대체하지 않는다. 새 브랜치는 `feature/frame-speed`를 기반으로 생성했으며, 해당 기반 브랜치의 변경을 모두 포함한다. 여기에 신규 학습 분석 코드와 문서 및 화면 변경을 추가했다. `main`에는 병합하지 않았다.

## 2. 기존 프레임 특징 캐시 최적화

### 기존 문제

A 단계의 판서 분석은 프레임마다 잉크 마스크, 전경 마스크, 잉크 선명도 등을 계산한다. 기존에는 Pages 단계가 비슷한 특징을 다시 계산해 동일한 영상 프레임을 중복 분석했다.

### 변경 사항

- A 단계에서 계산한 잉크 마스크, 전경 마스크, 프레임별 잉크 선명도를 공용 캐시에 저장한다.
- 마스크는 `np.packbits`로 압축하고, 128프레임 단위의 `.npz` 파일로 나눈다.
- 임시 파일 작성 후 원자적으로 교체한다.
- 캐시 버전과 배열 크기·프레임 수를 확인한다.
- 캐시가 없거나 손상되었거나 형식이 맞지 않으면 기존 계산 경로로 돌아간다.
- Pages 단계는 유효한 공용 캐시가 있으면 특징 계산을 재실행하지 않는다.

주요 파일은 `lecture2doc/feature_cache.py`, `lecture2doc/vision.py`, `lecture2doc/pages.py`, `lecture2doc/storage.py`다.

### 기존 통제 실험 결과

기반 브랜치의 한국어 성능 비교 보고서에 기록된 결과다.

| 측정 항목 | 기존 main | 캐시 최적화 브랜치 |
|---|---:|---:|
| A 단계 특징 분석 | 15.453초 | 15.310초 |
| Pages 특징 계산·캐시 읽기 | 11.602초 | 0.019초 |
| 두 측정 구간 합계 | 약 27.06초 | 약 15.33초 |

- 두 측정 구간 합계 감소율: 약 43.34%
- Pages 특징 계산·캐시 읽기 구간 감소율: 약 99.84%
- 잉크 마스크·전경 마스크는 바이트 단위로 동일했고, 잉크 선명도 배열도 동일했다.
- 판서 상태 수는 양쪽 모두 10개, 프레임 분석 지표 수는 양쪽 모두 150개였다.

**측정 범위와 한계:** 5분 길이의 합성 화이트보드 영상, 2초 샘플링 간격, 150개 프레임을 사용한 Linux 컨테이너 실험이다. A 분석과 Pages 특징 관측 구간만 비교했으며, 디코딩·전체 페이지 그룹화·복원·음성 전사·OCR을 포함한 전체 프로그램의 처리 시간은 아니다. 사용자의 Mac에서 같은 수치가 재현되는지도 아직 확인하지 않았다. 따라서 전체 앱이 43.34% 빨라졌다고 해석하면 안 된다.

## 3. 신규 기능: 강의 중요도 분석 및 필기·음성 연결

### 3.1 페이지별 중요도

각 판서 페이지에 대해 0~100의 중요도 점수, 중요도 등급, 계산 신호와 판단 근거를 저장한다.

페이지 중요도는 규칙 기반 신호로 계산하며, 개념 목록은 기본 필터를 거친 뒤 로컬 Qwen3-VL이 설치되어 있고 Ollama가 실행 중이면 AI가 강의 주제에 맞는 항목을 최대 5개 선별한다.

| 신호 | 현재 계산 방식 | 전체 자료가 있을 때 가중치 |
|---|---|---:|
| 교수자 강조 표현 | 시험·출제, 중요·핵심, 기억·암기, 주의·오류, 정의·공식, 유도·증명, 예제·문제 풀이 표현 탐지 | 40% |
| 관련 개념 반복 | 판서 개념이 음성 전사에서 다시 언급된 횟수 | 30% |
| 필기·음성 일치 | OCR에서 추출한 판서 개념 중 음성에서 확인된 개념의 비율 | 22% |
| 판서 근거 | 신뢰 가능한 OCR 필기 개념이 존재하는지 확인 | 8% |

전체 신호가 없을 때는 사용 가능한 신호의 가중치를 다시 정규화한다. 음성 전사가 없으면 교수자 설명의 중요도를 산정하지 않고 미산정 상태로 표시한다.

중요도 등급은 현재 65점 이상을 높음, 35점 이상을 보통, 35점 미만을 낮음으로 구분한다. 이 점수는 시험 출제 확률이나 정답 확률이 아니며, 실제 강의와 사람의 판단을 대조해 가중치를 조정해야 하는 초기 추정치다.

### 3.2 AI 기반 주제 개념 선별

OCR 판서와 음성 전사에서 후보 용어를 만들고 흔한 말버릇·조사·일반 표현을 제거한다. Ollama 로컬 Qwen3-VL이 설치되어 있으면 전사 일부와 신뢰 가능한 판서 OCR 일부, 후보 용어와 근거를 로컬 모델에 보내 강의 주제와 직접 연관된 개념을 최대 5개 선별한다. 후보에 있는 원문 표현과 연결되는 항목만 채택하므로 원문에 없는 개념을 새로 만들어 표시하지 않는다. 같은 개념의 표기 변형은 하나로 묶는다.

별도의 '현재 판서와 연결된 음성 설명' 영역은 일반 음성 전사와 중복되어 화면에서 삭제했다. 개념별 등장 시간에서 해당 개념이 실제로 언급된 전사 구간을 확인할 수 있다. Ollama가 실행되지 않거나 모델이 없으면 외부 AI 호출 없이 기본 필터 결과를 표시한다.

### 3.3 개념별 등장 시각

AI가 선별한 개념의 원문 표현을 전체 음성 전사에서 검색해 발언이 나온 구간을 저장한다. 한국어의 기본적인 조사 변형은 일부 정규화하고, 영문 단어는 단어 경계를 고려해 검색한다.

개념마다 다음 정보가 저장된다.

- 음성에서 언급된 모든 전사 구간과 원문
- 해당 개념이 읽힌 판서 페이지
- 판서 페이지의 시작·종료 시각
- 개념별 중요도와 판단 근거

주의할 점은 판서 시간은 기존 페이지 정리 단계가 기록한 페이지 범위라는 것이다. OCR로 인식한 개별 글자가 정확히 쓰인 순간을 추적한 값은 아니다. 음성 시간 역시 Whisper 또는 자막의 세그먼트 시간 경계를 따른다.

### 3.4 웹 화면

강의 기록 화면의 판서·영상·전사 영역 아래쪽 맨 마지막에 학습 분석 영역을 배치했다.

- **중요 판서 구간:** 중요도 순 상위 8개 페이지를 표시하고 근거와 시간 범위를 보여준다. 각 카드 아래에 해당 구간을 작은 화면으로 미리 재생할 수 있는 동영상 플레이어를 넣었다.
- **개념별 등장 시간:** AI가 선별한 최대 5개 개념의 필기·음성 등장 시각을 나열한다.
- **영상 이동:** 시간 항목을 클릭하면 원본 영상의 해당 시점부터 재생한다.
- **판서별 동영상 미리보기:** 각 중요 판서 카드 아래에 최대 320px 폭의 소형 플레이어를 제공한다. 재생 시 판서 시작점으로 이동하고 페이지 종료 시점에 멈춘다. 미리보기는 지연 로딩하며 대표 원본 프레임을 포스터로 표시한다.
- 중복되는 **현재 판서와 연결된 음성 설명** 패널은 삭제했다.

기존 강의에도 웹 화면의 **분석 다시 실행** 버튼으로 학습 분석만 다시 수행할 수 있다. 버튼을 누르면 해당 분석 캐시를 강제로 갱신하고 AI 개념 선별도 다시 요청한다. 단, 이 버튼은 이미 저장된 OCR·음성 전사 자료를 활용한다. 전사가 없으면 음성 등장 시각은 만들 수 없고, OCR이 없으면 판서 개념과의 연결이 제한된다.

## 4. 파이프라인과 저장 방식

전체 처리 흐름은 다음과 같다.

```text
영상 프레임 추출
  → A 판서 분석 및 공용 특징 캐시 저장
  → Pages 단계에서 공용 캐시 재사용
  → B 판서 복원
  → 음성 전사 또는 자막 처리
  → C OCR
  → D 강의 중요도·개념 등장 시간 분석
  → manifest.json 및 웹 화면 반영
```

신규 분석은 `lecture2doc/learning_analysis.py`에서 수행하고, `pipeline.py`가 OCR 이후 분석 단계를 실행한다. 결과는 `manifest.json`의 `learning_analysis` 필드에 저장된다.

분석은 `learning-analysis`라는 별도 단계 캐시를 사용한다. 캐시 지문에는 원본 영상 해시, 페이지 ID·시간, 전사 ID·시간·원문, OCR 텍스트·점수가 포함된다. 입력 자료나 분석 버전이 바뀌면 기존 결과를 그대로 재사용하지 않는다.

기존 강의를 웹에서 다시 분석하는 API도 추가했다. 이 API는 저장된 manifest를 읽고 학습 분석 결과와 단계 시간을 갱신한다.

## 6. 테스트 및 검증 상태

이번 브랜치에는 분석 로직 단위 테스트 10개를 추가했다. Qwen 연결 테스트 4개와 OCR 웹 API 테스트도 별도로 보강했다.

1. 판서 개념이 음성에서 언급된 시간과 해당 발언을 연결하는지
2. 음성 전사만 있는 경우 부분 분석으로 동작하는지
3. 음성 없이 OCR만 있는 경우 중요도를 임의로 만들어내지 않는지
4. 판서·음성 자료가 모두 없는 경우 근거 부족으로 처리하는지
5. 낮은 신뢰도로 검수 표시된 OCR 텍스트가 판서 근거로 사용되지 않는지
6. 일반 표현을 핵심 개념에서 제외하는지
7. 로컬 Qwen이 기존 후보 중에서만 개념을 선별하는지
8. Qwen 모델이 없는 경우 기본 필터로 대체하는지
9. OCR 원본 결과를 보존하면서 Qwen 결과를 별도 저장하는지
6. '한번', '것도' 등 일반 표현을 개념 후보에서 제외하는지
7. AI가 기존 후보 안에서만 핵심 개념을 선별하고 관련 시간 정보를 보존하는지
8. AI가 설정되지 않은 경우 기본 필터로 최대 5개만 표시하는지

**중요:** 이 대화의 작업 환경에서는 새 브랜치의 Python 테스트를 실제 실행하지 못했다. 따라서 위 항목은 테스트 코드가 작성된 상태이며, 통과가 확인된 상태는 아니다. Mac에서 아래 명령으로 실행한 뒤 결과를 확인해야 한다.

```bash
python -m pytest tests/test_learning_analysis.py -q
python -m pytest tests/test_feature_cache.py -q
python -m pytest -q
```

또한 실제 강의에서 중요도 순위가 사람이 판단한 핵심 구간과 일치하는지, 한국어 OCR과 음성 전사에서 개념이 올바르게 연결되는지 검증이 필요하다.

## 7. 현재 한계 및 후속 개선

- 페이지 중요도는 규칙 기반이며, 개념 선별은 로컬 Qwen 모델이 설치·실행 중일 때 AI 문맥 분석을 추가한다. 모델이 없으면 문자열 기반 기본 필터로 대체한다.
- 한국어 조사는 일부 정규화하지만 완전한 형태소 분석은 아니다.
- OCR 오인식 및 음성 전사 오류는 개념 추출과 시간 연결에 영향을 준다.
- 교수자가 중요하다고 말하지 않아도 중요한 내용일 수 있고, 강조 표현이 있다고 모두 시험에 중요한 것은 아니다.
- 중요도 점수는 실제 학습 효과나 시험 출제 가능성을 검증한 값이 아니다.
- 페이지의 시작·종료 시간은 개별 필기의 정확한 작성 시각을 뜻하지 않는다.
- 공용 특징 캐시의 기존 성능 결과는 Linux 합성 영상 실험이다. 실제 Mac 및 긴 강의 영상에서 별도 측정이 필요하다.

다음 단계는 실제 강의 1~2개에서 사람 기준 중요 구간을 표시하고, 자동 순위와 비교하는 것이다. 그 결과를 바탕으로 강조 표현, 반복성, 필기·음성 일치의 가중치와 개념 추출 방식을 조정한다.

## 8. Mac 실행 방법

### 8.1 새 브랜치 가져오기

저장소에 수정 중인 파일이 있는지 먼저 확인한다.

```bash
cd ~/Lecture2Doc
git status --short
```

출력이 비어 있고 작업 내용이 깨끗하면 다음을 실행한다.

```bash
git fetch origin
git switch --track "origin/기능/강의-중요도-시간연결.time"
```

이미 같은 로컬 브랜치가 있다면 다음 명령을 쓴다.

```bash
git switch "기능/강의-중요도-시간연결.time"
git pull --ff-only origin "기능/강의-중요도-시간연결.time"
```

작업 중인 수정 사항이 있으면 먼저 별도 커밋하거나 안전하게 보관한 다음 브랜치를 변경한다.

### 8.2 가상환경 및 패키지 준비

프로젝트 루트에서 기존 가상환경을 활성화한다.

```bash
source .venv/bin/activate
python --version
python -m pip install -e '.[ocr,stt,test]'
```

Python 3.11 이상이 필요하다. 영상 처리에는 FFmpeg와 ffprobe도 필요하다.

### 8.3 OCR 모델 준비

한글 판서가 있다면 한글 모델을 준비한다.

```bash
lecture2doc ocr-models --language ko
```

처음 실행할 때 모델을 내려받는다. 이미 준비되어 있으면 다시 다운로드할 필요가 없다.

### 8.4 AI 키 설정 및 웹 앱 실행

로컬 Qwen 기능을 사용할 때는 Ollama 0.12.7 이상을 설치하고 앱을 실행한 다음 모델을 내려받는다.

```bash
lecture2doc qwen-models
./serve.sh
```

기본 모델은 `qwen3-vl:4b`이며 약 3.3GB다. 모델 설치 안내는 `docs/QWEN_LOCAL.md`에 기록했다.

키를 설정하지 않으면 기본 필터만 사용하고 외부 AI 호출은 하지 않는다.

브라우저에서 `http://127.0.0.1:8765`를 연다. 서버를 종료하려면 실행한 터미널에서 `Ctrl+C`를 누른다.

### 8.5 새 강의 분석

웹 화면에서 강의를 등록할 때 다음을 설정한다.

- 판서 OCR: 한글이 포함되어 있으면 **한글·영문**
- Whisper 모델: `base` 또는 준비된 모델
- 음성 언어: 한국어 강의면 `ko`
- 최초 모델 다운로드가 필요하면 다운로드 허용 체크

이미 자막 파일(SRT/VTT)이 있다면 영상과 함께 등록해 Whisper 전사를 대신할 수 있다. 음성 전사 또는 자막이 있어야 개념의 음성 등장 시각을 만들 수 있다. Qwen 모델이 준비되어 있으면 전사와 OCR 텍스트 일부를 Mac의 Ollama로 전달해 핵심 개념을 선별한다. 외부 API로 전송하지 않는다.

처리가 끝나면 강의 화면의 **강의 중요도와 개념 등장 시간** 영역을 확인한다.

### 8.6 기존에 처리한 강의 분석

기존 강의 기록에 OCR과 음성 전사 결과가 이미 있다면 강의 화면에서 **분석 다시 실행**을 누른다. 이 작업은 영상 디코딩·판서 복원·OCR을 다시 수행하지 않고 저장된 결과를 사용하며, 학습 분석 캐시를 새로 계산한다.

기존 기록에 음성 전사가 없으면 분석 버튼만으로 전사가 새로 만들어지지는 않는다. 이때는 자막을 준비하거나 Whisper 전사를 먼저 실행한 뒤 학습 분석을 다시 해야 한다. CLI로 같은 원본과 출력 폴더를 사용해 처리하면 기존 단계 캐시를 재사용할 수 있다. 예를 들어 실제 파일명이 `source.mp4`인 기록은 다음과 같이 실행한다.

```bash
lecture2doc process data/<강의ID>/source.mp4 \
  --out data/<강의ID> \
  --model base --language ko --allow-download --ocr ko
```

실제 원본 확장자와 폴더 이름은 해당 강의 기록에 맞춘다. 이미 분석 결과가 있고 학습 분석만 강제로 갱신하려면 명령에 `--rerun learning-analysis`를 추가한다. 로컬 Qwen 모델이 설치되어 실행 중이면 Qwen 개념 선별도 새로 수행한다.

### 8.7 테스트 실행

```bash
python -m pytest tests/test_learning_analysis.py -q
python -m pytest tests/test_feature_cache.py -q
python -m pytest -q
```

## 10. 한국어 OCR 모델 기본값 조정

초기 `korean-handwriting-rec` 기본 적용 후 실제 강의 화면에서 한국어·영어 혼합 문장과 영문 표기가 악화되는 사례를 확인했다. 이에 기본 인식기를 한국어와 영어를 지원하는 PP-OCRv5 Korean Mobile로 되돌리고, 손글씨 파인튜닝 모델은 `LECTURE2DOC_KO_RECOGNIZER=handwriting`으로 선택하는 비교용 모델로 유지한다. 기존 강의는 서버 재시작 후 C · 판서 텍스트의 **OCR 다시 실행** 버튼으로 다시 인식해야 하며, 화면에서 실제 선택된 모델명을 확인한다.

## 12. 최신 Qwen 모델 자동 선택 및 필수 다운로드 세트 통합

2026년 11월 기준 최신 공개 Qwen 비전·언어 모델 Qwen3.8-27B를 로컬 Ollama 실행 후보에 추가했다. Apple Silicon용 `qwen3.8:27b-mlx`는 약 18GB이며 이미지 입력을 지원한다. Qwen3.8-27B 가중치의 공개 라이선스는 Apache-2.0이다.

Mac 메모리별 자동 선택은 다음과 같다.

| 통합 메모리 | 선택 모델 | 대략적인 다운로드 크기 |
|---|---|---:|
| Apple Silicon 32GB 이상 | `qwen3.8:27b-mlx` | 약 18GB |
| 24GB 이상 | `qwen3-vl:8b` | 약 6.2GB |
| 16GB 이상 24GB 미만 | `qwen3-vl:4b` | 약 3.3GB |
| 16GB 미만 | `qwen3-vl:2b` | 약 1.9GB |
| 메모리 감지 실패 | `qwen3-vl:4b` | 약 3.3GB |

`lecture2doc setup-models` 통합 명령을 추가했다. Ollama 실행 및 버전을 먼저 확인한 뒤 영문·한글 OCR 모델과 메모리에 맞는 Qwen 모델을 함께 내려받는다. OCR 모델만 또는 Qwen 모델만 필요한 경우 기존 `ocr-models`, `qwen-models` 명령도 유지한다.

다운로드에 성공한 Qwen 모델 선택은 `models/qwen/selection.json`에 기록해 프로그램을 재실행해도 같은 모델을 계속 사용한다. 이 설정 파일과 모델 가중치는 Git에서 제외한다. `LECTURE2DOC_QWEN_MODEL` 환경 변수는 저장된 선택보다 우선한다. 메모리 사양이 바뀌거나 자동 추천을 다시 적용하려면 `lecture2doc setup-models`를 다시 실행한다.

Qwen 비전 모델 하나가 C · 판서 이미지 재검토와 D · 핵심 개념 선별의 텍스트 분석을 함께 담당한다. 추론은 Ollama 로컬 서버에서 실행하며 외부 AI API 토큰 비용은 발생하지 않는다. 최초 다운로드에는 인터넷 연결이 필요하고, 이후 추론은 Mac의 메모리·연산 자원을 사용한다.

추가된 테스트는 메모리별 자동 선택, Ollama 버전 확인, 로컬 모델 선택 저장·재사용, 필수 모델 통합 다운로드 경로를 확인한다. 테스트 코드는 추가했으나 이 대화의 원격 GitHub 편집 환경에서는 실제 pytest를 실행하지 않았다.
